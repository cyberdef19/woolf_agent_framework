Проект майбутня основа під більш крупну ідею, однак на цій платформі прийняв рішення робити домашні завдання також. Проект розділено на декілька частин: файли з домашніми завданнями: assignments, вихідні файли у src з основним кодом платформи, tests - тестова частина. 
Щоб запустити 1-шу домашню роботу, слід працювати з файлом assignments\assignment_01\main.py. Реалізовано інструменти з виклику сервісів, що працюють з тестовим файлом: отримання метаданих файла, отримання хеша файла та отримання рядків з файла. 
В роботі реалізовано: граф типу tool calling - реалізований у ToolCallingAgent. Налаштування через OpenRouter з різними моделями free, а також рядом платних моделей. LLMSettings підтримує ряд параметрів при виконанні запиту до LLM, такий як локальний llm timeout, максимальна кількість спроб звернення до llm. Також, реалізовано StopController, який надає також умови виходу з цикла викликів інструментів. Реалізовано також специфікацію агента AgentSpec з метою, правилами, інструкціями тощо - передається у агента як системне повідомлення. Також, реалізовано retry політики з використанням tenacity бібліотеки.
До кожного інструмента на основі Pydantic реалізовано input-и, а також типи схеми для отримання результатів, як часткових так і загального. Для завдання 1 - загальний результат в AssignmentResult01, також спільний стан у Assignment01AgentState. Реалізовано сериалізацію траекторій у json файли.
Окремо, подано 3 тести

Перше завдання запускається з assignments\assignment_01\main.py. Тестове завдання запускається pyuthon -m pytest tests/tests_assignment_01.py -v

У межах роботи реалізовано асинхронного tool-calling агента на базі LangGraph для первинного аналізу цифрових артефактів. Агент здатний самостійно обирати необхідний інструмент відповідно до запиту користувача та виконувати отримання метаданих файла, розрахунок криптографічного хешу і вилучення читабельних рядків. Інструменти ізольовані від агентної логіки через сервісний шар і типізовані Pydantic-моделі. Додатково реалізовано механізми обмеження виконання, retry, timeout та журналювання траєкторії. Результати тестування на локальному артефакті підтвердили працездатність усіх трьох операцій та формування структурованого фінального результату. Окремо виявлено залежність надійності structured output від конкретної LLM та її provider-а. Так, ця залежність виявилася при використанні openai/gpt-oss-20b:free - намагається віддавати у відвідь на запит with_structured_output власну схему відповіді, ігноруючи користувацьку pydantic схему результату. Дуже важко добитися від безкоштовних агентів роботи без timeout.
