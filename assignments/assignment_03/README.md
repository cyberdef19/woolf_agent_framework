Для запуску прототипа агента, що має на меті відповідати на історичні питання, наприклад: Яке походження назви Хаджибей? Визнач представлені в доступних джерелах гіпотези та оціни, яка з них має найкращу доказову підтримку.Векторна база поки містить невелику тестову кількість джерел про історичний Хаджибей - буде істотно збільшуватися згодом. В розпоряджені агента декілька інструментів: 
-пошук джерел в RAG;
-пошук за відкритими джерелами у веб з використанням Tavily;
-можжливість розширення контексту знайдених документів в RAG;
-пошук пов'язаних джерел.

Реалізовано агент планувальник, який працює у зв'язці з ReAct агентом, який формує json-схеми для того, щоб середовище виконання змогло виконати інструменти. 
Агент планувальник складений з ряда вузлів MultiAgentPlanerExecutor: 
- вузол-планувальник - планує перший план для виконання завдання користувача по крокам.
- вузол-виконувач - виконує кроки плана, шляхом виклику або ReAct агента, або викликом воркерів для роботи з іншими кроками: воркер-reasoning проводить міркування над історичними гіпотезами; воркер оцінювач виконання кроку виконує оцінку кроку і якщо потрібно визначає чи потрібно план переплановувати, чи продовжувати виконання поточних кроків плану чи зробити human-ni-the-loop; воркер-оцінювач плану цілком оцінює повне виконання плану і визначає чи потрібно позначати виконання як завершене чи відправляти його на перепланування. 
- вузол-лічильник - веде облік поточних кроків виконання плану.
- вузол-перепланувальник - здійснює перепланування поточного плану.
- вузол-переривач - здійснює роботу з переривання потоку виконання для задіяння у циклі людини.
- вузол підготовки завершальної відповіді готує відповідь для користувача.
- маэ в складі роутер

ReAct-агент ToolCallingGraph також складається з декількох вузлів:
- вузол для формування виклику інструментів.
- вузол для формування завершальної відповіді.
- вузол _stop_guard_node та роутер

Виклики агентів обслуговуються спільним llm invoke-ром LLMExecutor.

Для MultiAgentPlanerExecutor реалізовано checkpointer. RAG-складається з 11 документів, що зберігаються у векторній базі даних Chroma. Пошук документів відбувається зазвичай на першому кроці відповіді, коли агент вирішує, що потрібні історичні джерела для формування відповіді. Окремим вузлом реалізовано перехоплення потоку для HITL. Користувач може підтвердити, відхилити запитане агентом через термінал.
